# מדריך הסקריפטים — Alerts

אוסף סקריפטי Bash גנריים לניטור והתראות על שרתי Linux.
כל סקריפט מוגדר בפרמטרים בשורת הפקודה, כך שאפשר להשתמש בו שוב ושוב לשגיאות, ספים, שירותים ותיקיות שונים, בלי לשנות קוד.

## למי זה מתאים

הסקריפטים בנויים לפי תקן ה-plugins של Nagios, ולכן מתאימים ל:

- **כלי ניטור** בסגנון Nagios (Nagios, Centreon, Icinga ודומיהם).
- **Control-M**: כ-job שנכשל כשמתגלה בעיה. כל exit code שונה מ-0 נחשב כשל, וכך מופעלת התראה או פעולת On-Do.
- **הרצה ידנית או cron**: לבדיקה מהירה משורת הפקודה.

## עקרונות משותפים לכל הסקריפטים

| Exit code | משמעות |
|---|---|
| 0 | OK, הכל תקין |
| 1 | WARNING, עבר את סף האזהרה |
| 2 | CRITICAL, עבר את הסף הקריטי או שמשהו חסר |
| 3 | UNKNOWN, פרמטרים שגויים, קובץ לא קיים וכו' |

- **פלט**: שורת סטטוס אחת שמובנת לאדם, ואחרי התו `|` נתוני ביצועים (perfdata) לגרפים.
- **ספים**: `-w` לאזהרה, `-c` לקריטי.
- **עזרה**: כל סקריפט מציג את כל האפשרויות עם `-h`.
- **תלויות**: אין. רק Bash וכלים סטנדרטיים של Linux.

## 1. check_log_pattern.sh — תפיסת שגיאה בלוג

**מה הוא עושה:** מחפש ביטוי (regex) בקובץ לוג, ומתריע כשמספר ההופעות עובר את הסף.

**איך הוא עובד:**
- אפשר לתת קובץ מסוים (`-F`), או תיקייה ותבנית שם (`-d`, `-f`). במקרה השני נבדק הקובץ החדש ביותר שמתאים.
- **בודק רק שורות חדשות**: הסקריפט שומר את המיקום האחרון שקרא, כך ששגיאה ישנה לא מתריעה שוב ושוב.
- מזהה סבב לוגים (rotation) או קובץ שהתאפס, ומתחיל לקרוא מההתחלה.
- אפשר להחריג שורות (`-x`), למשל שגיאות ידועות שאין צורך להתריע עליהן.
- אפשר להתריע גם אם הלוג לא התעדכן X דקות (`-a`), סימן שהאפליקציה אולי נתקעה.

**דוגמאות:**

<div dir="ltr">

```bash
# CRITICAL על כל שגיאת ORA- בקובץ app*.log החדש ביותר
./check_log_pattern.sh -d /opt/app/logs -f 'app*.log' -p 'ORA-[0-9]+'

# שגיאות SIP: אזהרה מ-5, קריטי מ-20, בלי 401
./check_log_pattern.sh -F /var/log/asterisk/messages -p 'SIP/2.0 [45][0-9]{2}' -x 'SIP/2.0 401' -w 5 -c 20
```

</div>

## 2. check_cpu.sh — ניטור CPU

**מה הוא עושה:** מודד עומס מעבד ומתריע לפי ספים. המדידה נעשית על פני כמה שניות (`-t`, ברירת מחדל 3), כדי שקפיצה רגעית לא תטעה.

**מצבי בדיקה (`-m`):**

| מצב | מה נמדד |
|---|---|
| `total` | אחוז ניצול CPU כולל (ברירת מחדל) |
| `iowait` | אחוז זמן המתנה לדיסק, מעיד על צוואר בקבוק באחסון |
| `load` | Load average לכל ליבה (1.0 = ליבה עמוסה במלואה) |
| `process` | ניצול CPU של תהליך מסוים (100% = ליבה אחת מלאה) |

**דוגמאות:**

<div dir="ltr">

```bash
./check_cpu.sh -w 80 -c 95                          # CPU כולל
./check_cpu.sh -m iowait -w 20 -c 40                # המתנה לדיסק
./check_cpu.sh -m process -p asterisk -w 50 -c 90   # תהליך מסוים
```

</div>

## 3. check_service.sh — האם שירות למעלה

**מה הוא עושה:** בודק שירות באחת או יותר מהשיטות הבאות. כל הבדיקות שהוגדרו חייבות לעבור, וכל כשל הוא CRITICAL.

| פרמטר | בדיקה |
|---|---|
| `-s` | שירות systemd במצב active |
| `-p` | תהליך רץ לפי שם מדויק. `-f` מאפשר חיפוש בכל שורת הפקודה. `-n` קובע מינימום תהליכים |
| `-P` | פורט TCP פתוח ומקבל חיבורים, מקומי או מרוחק (`-H`) |

השילוב שימושי: שירות יכול להיות "active" ב-systemd ועדיין לא להאזין לפורט. בדיקה משולבת תופסת את זה.

**דוגמאות:**

<div dir="ltr">

```bash
./check_service.sh -s asterisk -P 5060          # השירות פעיל וגם מאזין
./check_service.sh -p kamailio -n 4             # לפחות 4 תהליכים
./check_service.sh -H 10.0.0.5 -P 443 -T 3      # פורט בשרת מרוחק
```

</div>

## 4. check_dir.sh — בדיקת תיקיות

**מה הוא עושה:** בודק תיקייה אחת או כמה תיקיות בבדיקה אחת. כדי לבדוק כמה, חוזרים על `-d` או מפרידים בפסיקים. הסטטוס הסופי הוא החמור ביותר מבין כל התיקיות, ותיקייה חסרה היא תמיד CRITICAL.

**מצבי בדיקה (`-m`):**

| מצב | מה נבדק | שימוש טיפוסי |
|---|---|---|
| `exists` | התיקייה קיימת ונגישה (ברירת מחדל) | mount שנפל, הרשאות |
| `count` | מספר קבצים | הצטברות קבצים שלא מעובדים (backlog) |
| `oldest` | גיל הקובץ הישן ביותר, בדקות | קבצים "תקועים" שלא נאספו או נשלחו |
| `newest` | גיל הקובץ החדש ביותר, בדקות | לא הגיעו קבצים חדשים, תהליך הזנה נעצר |
| `size` | גודל כולל ב-MB | תיקייה שמתמלאת |
| `empty` | התיקייה ריקה | קבצים שאמורים להיות ואינם |

אפשר לסנן לפי שם קובץ (`-f '*.csv'`) ולכלול תתי-תיקיות (`-r`).

**דוגמאות:**

<div dir="ltr">

```bash
./check_dir.sh -d /data/in,/data/out -m count -w 100 -c 500   # הצטברות קבצים
./check_dir.sh -d /transfer/outgoing -m oldest -w 30 -c 60    # קבצים תקועים
./check_dir.sh -d /data/in -m newest -f '*.csv' -w 60 -c 120  # לא הגיע קובץ חדש
```

</div>

## התקנה ושילוב

<div dir="ltr">

```bash
git clone https://github.com/ItamarBenMenda/alerts.git
cd alerts && chmod +x *.sh
# כלי ניטור בסגנון Nagios: העתקה לתיקיית ה-plugins
cp *.sh /usr/lib/nagios/plugins/
```

</div>

- **בכלי ניטור**: מגדירים command שמריץ את הסקריפט עם הפרמטרים, ומשייכים אותו ל-service.
- **ב-Control-M**: מגדירים job מסוג Command או Script שמריץ את הסקריפט. כשל (exit code שונה מ-0) מפעיל את ההתראה.
- **הרשאות**: המשתמש שמריץ את הבדיקות צריך הרשאת קריאה ללוגים ולתיקיות הנבדקות. `check_log_pattern.sh` צריך גם הרשאת כתיבה לתיקיית ה-state (ברירת מחדל `/var/tmp/check_log_pattern`).

</div>
